# Faceless 2 JavaScript room directory (Node 22)

This is a real in-memory **room registration / discovery / signaling directory** written in JavaScript with no npm dependencies. It is **not** the transport for Godot game packets and **not** a TURN relay or a full WebRTC signaling/ICE stack. The Godot Android client uses HTTPS to create/list/resolve codes, then opens a native direct ENet/UDP connection to the host. Hosts still require a reachable UDP port. The default build works without any directory for same-Wi-Fi room discovery, but the service must be deployed for public Internet listings.

Run tests: `node --test matchmaking/server.test.mjs`. Local development: `PORT=8787 node matchmaking/server.mjs`, and set `http://127.0.0.1:8787` as directory in the game (loopback allowed only for tests). Production: put Node behind a TLS-terminating reverse proxy, set `TRUST_PROXY=1` only behind an **authenticated/trusted** proxy that overwrites `X-Forwarded-For`, and enter its HTTPS base URL in the lobby. The directory cannot automatically provision DNS, TLS or a home-router UDP mapping. For public Internet joins, UPnP/manual port forwarding and no symmetric/CGNAT blockade are necessary; otherwise a true relay/TURN design is future work.

`POST /v1/rooms` creates room (name, port, max_players=2..4, public=true|false), returning room code, owner token, key. `GET /v1/rooms` lists only public rooms and no IPs or secrets. `GET /v1/rooms/CODE` resolves any room by its code (including private rooms) and returns the host endpoint. Authenticated `POST /v1/rooms/CODE/heartbeat` updates active seat count and TTL; `DELETE /v1/rooms/CODE` destroys the listing. Rooms expire after 45 seconds without a heartbeat. The service is intentionally non-persistent and must be run as a single instance without a shared store. A durable scaled service requires storage, rate limiting at the reverse proxy and abuse monitoring.

Security notes: room codes are unguessable enough for casual private entry, **not end-to-end encryption**. Hosts must keep player authority and distance checks; directory metadata is not trusted for gameplay. Do not share the owner token. This MVP does not provide account identity, DDoS resistance, persistent storage, strong abuse protections, cross-network NAT traversal, or fallback relays.
